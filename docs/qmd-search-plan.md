# qmd 搜索接入计划

状态：代码已实现。本文保留 org-wiki 的 qmd 搜索设计、实施分工和验收条件；使用步骤见 README，实测版本和输出见 [CLI 契约](qmd-cli-contract.md)。完整查询集的效果评估仍作为独立工作。

本文中的 qmd 指 [tobi/qmd](https://github.com/tobi/qmd)，不是 Quarto 的 `.qmd` 文档格式。

## 1. 目标与推荐方案

增加可选的 qmd 搜索后端，让 Emacs 命令、MCP 和 gptel 共用接入结果。推荐采用以下路径：

```text
Org Wiki 节点
  → 按 canonical heading ID 生成 Markdown 缓存
  → qmd 独立索引、专用 collection
  → qmd CLI 返回 JSON 搜索结果
  → 映射并校验原始 Org 节点
  → 现有节点摘要、读取、引用和跳转
```

首个可用版本先接通 qmd 关键词检索，再增加向量与混合检索。qmd 是可选外部程序，搜索接入默认关闭；普通安装不依赖 qmd，默认配置维持现有搜索行为。查询只读取知识库，索引维护只写派生缓存。

本轮范围包括搜索路由、节点缓存、索引维护、CLI 适配、状态诊断和验证。知识库内容编辑、源材料导入和远程 qmd 服务留到后续工作。

## 2. 现有代码的接入点

现有实现提供以下基础：

| 位置 | 已有行为 | 计划调整 |
| --- | --- | --- |
| `org-wiki.el`：`org-wiki--search` | org-ql-semantic 优先，失败或空结果时回退字面搜索 | 增加后端选择，保持参数和结果结构 |
| `org-wiki.el`：候选发现辅助函数 | 合并根目录与 org-roam 中带 `WIKI_KIND` 的文件；org-roam 查询失败时返回空值 | 为同步增加带完整性状态的发现接口，保留现有查询端的容错行为 |
| `org-wiki.el`：节点摘要、ID 解析 | 返回 canonical heading ID 和原始 Org 信息；摘要目前只识别固定层级的 `** Summary`，读取依赖 `org-id-locations` | 按节点层级提取摘要，并把已验证的 canonical ID 位置接入现有读取和跳转路径 |
| `org-wiki-commands.el`：`org-wiki-search` | 调用统一搜索；前缀参数强制字面搜索 | 保留前缀行为，更新帮助文字 |
| `org-wiki-mcp.el`、`org-wiki-gptel.el` | 通过 `org-wiki--search` 暴露 `wiki_search(query, k)` | 保持工具协议，补充集成回归验证 |

统一结果仍为 `:id`、`:title`、`:kind`、`:file`、`:summary`。其中 `:file` 指向原始 Org 文件，`:summary` 从原始节点提取。qmd 的文档标识、缓存路径、命中片段与分数只用于适配器内部。

## 3. 明确索引粒度

qmd 官方源码已有 `.org` 标题提取，因此可以研究直接索引 Org 文件；但这一能力不能解决“文件命中对应哪个 wiki 标题”的问题。源码也包含按 Markdown 标题寻找分块边界的逻辑。参见 [qmd 的标题提取与分块实现](https://github.com/tobi/qmd/blob/main/src/store.ts)。

本方案选择“一 wiki 节点一 Markdown 缓存文件”，原因是：

- wiki 身份由标题上的 `WIKI_KIND` 决定，路径与文件标题不能替代节点身份。
- 一个 Org 文件可能混有 wiki 与普通笔记，直接索引整个文件可能因无关正文召回 wiki 节点。
- 命中 Summary、Definition 等子标题时，应返回拥有这些内容的 wiki 节点。
- 稳定的节点级映射能避开 qmd 行号、片段格式和文件级 ID 的歧义。

缓存生成约定如下：

1. 使用与现有候选发现相同的来源，枚举具有本地 `WIKI_KIND` 属性的标题；同步必须另外取得各来源的完整性状态，不能把容错后的空文件列表当作删除依据，详见第 6 节。
2. 使用标题级 canonical ID 建立映射；缓存文件名由 ID 的稳定安全编码或摘要生成，不直接拼接任意 ID。
3. 缓存正文包含标题、kind、Summary 与节点正文，保留普通子标题、链接说明和代码文本。若子树中另有 wiki 节点，内容归最近的 wiki 祖先，避免交叉归属。
4. 使用受控的 Org 到 Markdown 转换，不求值 Babel，不展开 INCLUDE，不读取链接目标。排除维护用属性抽屉；保留检索所需内容。
5. 单独维护 manifest：缓存相对路径 → canonical ID、原始文件、内容指纹、导出格式版本；记录知识库身份、发现范围和同步代次。只接受已提交代次的 manifest 内的命中。
6. 缺少 ID 或重复 ID 的节点不发布到索引，输出可定位的诊断，不自动修改 Org 文件。

摘要提取同步调整现有 `org-wiki--extract-summary`：以当前 wiki 标题层级为基准，只选择直属、标题为 `Summary` 且自身不是 wiki 节点的子标题，提取其正文及普通后代，遇到嵌套 wiki 子树时排除该子树。多个直属 Summary 时取第一个；没有直属 Summary 时返回空字符串，不借用后代 wiki 的摘要。节点缓存与所有搜索后端共用该规则；缓存正文中已有 Summary 时不重复附加摘要。原有一级节点的 `** Summary` 行为保留，二级及更深节点同样适用。

## 4. 后端选择与回退

以下为配置项：

| 配置 | 建议语义 |
| --- | --- |
| `org-wiki-search-backend` | `auto`、`qmd`、`org-ql-semantic`、`text`；默认 `auto` |
| `org-wiki-qmd-enabled` | qmd 搜索开关，布尔值，默认 `nil`；关闭时所有搜索入口均跳过 qmd |
| `org-wiki-qmd-program` | qmd 可执行程序路径 |
| `org-wiki-qmd-index-name` | org-wiki 专用索引名，隔离其他 collection 和更新钩子 |
| `org-wiki-qmd-collection` | 显式配置的专用 collection；默认未配置，是开启搜索开关后使用 qmd 的必要条件 |
| `org-wiki-qmd-cache-directory` | 按知识库身份隔离的派生缓存目录 |
| `org-wiki-qmd-discovery-scope` | 默认 `root-and-roam`；用户可显式选择 `root-only`，范围写入 manifest，来源故障不自动缩小范围 |
| `org-wiki-qmd-search-mode` | `search`、`vsearch`、`query`；首版默认 `search` |
| `org-wiki-qmd-search-timeout` | 搜索总超时；索引维护使用独立限制 |
| `org-wiki-qmd-models` | 预下载的本地 GGUF 路径 plist；`vsearch` 需 `:embed` 和查询扩展用的 `:generate`，混合检索另需 `:rerank`；embedding 维护只需 `:embed` |

路由行为如下：

| 选择 | 搜索顺序 |
| --- | --- |
| `auto`，qmd 开关已开启、已配置且索引就绪 | qmd → org-ql-semantic → 字面搜索 |
| `auto`，qmd 开关关闭、未配置或未就绪 | org-ql-semantic → 字面搜索 |
| `qmd`，开关已开启且就绪 | qmd → 字面搜索，同时记录 qmd 降级原因 |
| `qmd`，开关关闭、未配置或未就绪 | 直接字面搜索，记录禁用或未就绪原因 |
| `org-ql-semantic` | 保持已有语义搜索 → 字面搜索 |
| `text` 或交互前缀参数 | 直接使用现有字面搜索 |

开关优先于后端选择：即使 `org-wiki-search-backend` 为 `qmd`，`org-wiki-qmd-enabled` 为 `nil` 时搜索也不得启动 qmd 进程，包括版本与状态探测。仅安装程序、配置 collection 或运行 setup 不会自动开启搜索。开关通过 Customize 或 `setq` 修改，对后续查询立即生效；关闭时保留已有缓存和索引，重新开启后仍须检查就绪状态。切换开关本身不启动安装、同步或模型下载，也不取消已经显式启动的维护任务。

该开关控制搜索接入；用户显式调用 setup、sync、embed 时仍可准备索引，便于先构建后启用。status 应分别展示“搜索已禁用”与索引是否就绪，关闭时只读取本地状态。未来的自动维护调度也必须受此开关约束。

配置示例：

```elisp
;; 完成 setup 和 sync 后，允许 auto 使用 qmd。
(setq org-wiki-search-backend 'auto
      org-wiki-qmd-enabled t)

;; 关闭 qmd 搜索，auto 恢复原有语义搜索与字面回退。
(setq org-wiki-qmd-enabled nil)
```

后端错误和过滤后的空结果触发回退；非空结果按该后端排名返回，首版不混合不同后端的分数。空查询直接走已有字面发现路径。节点去重和有效性过滤后再应用 `k`；为过滤预留有上限的过量召回，必要时扩大候选数。

qmd 官方提供 `search`、`vsearch`、`query` 三种模式，以及 collection 限定、命名索引和 JSON 输出。向量维护通过 `embed` 完成，文档更新通过 `update` 完成。参见 [qmd 官方使用说明](https://github.com/tobi/qmd#cli-reference)。

## 5. CLI 适配与结果验证

新增 `org-wiki-qmd.el`，集中负责 qmd 进程、输出解析和结果映射。核心模块只负责选择后端，避免让 MCP 或 gptel 直接依赖 qmd。

适配器遵循以下规则：

- 使用 `make-process` 的参数列表启动程序，查询字符串作为单个参数传入。验证以 `-` 开头的查询，按锁定版本的参数解析规则处理，避免被识别为选项。
- 每次指定专用索引和 collection；工作目录设为受控缓存目录，避免意外采用调用者目录中的 qmd 项目配置。
- 分离 stdout JSON 与 stderr 日志。设置超时、输出大小上限；超时或用户 `C-g` 时终止子进程，释放临时 buffer。用户主动取消直接结束，不启动回退。
- CLI 进程以异步方式运行；第一版保持现有同步搜索函数签名，用可中断的等待封装兼容三种调用方。完成交互实测后再考虑扩展 gptel 异步回调。
- 解析锁定版本的真实 JSON，不从格式化文本提取信息；校验字段类型，并容忍无关新增字段。
- 将 qmd URI 或文件字段规范化为专用缓存内的 manifest 路径；拒绝其他 collection、目录穿越和未知映射。
- 根据映射定位原始 Org 标题，重新检查 ID、`WIKI_KIND` 和文件是否存在；文件路径做 truename 归一化，兼容符号链接。
- 成功发布同步结果以及返回搜索命中前，将已验证的 canonical ID → 原始文件位置登记到当前 Emacs 的 `org-id-locations`，让现有读取、引用和跳转使用同一位置。登记仅更新内存，不改写 Org 文件，也不强制保存全局 ID 位置文件；重启后首次 qmd 命中必须重新验证并登记，不能假定位置表已经预热。旧位置失效时修正；若旧位置仍包含同一 ID 的另一个有效节点，则报告冲突并排除命中，不静默覆盖。
- 同一节点多次命中时保留最佳排名，按 canonical ID 去重。返回摘要从原始 Org 生成，避免把索引片段当作知识库事实。

查询过程中不创建 collection、不运行文档更新或 embedding。qmd 自身可能写查询缓存；知识库正文始终只读。

## 6. 索引生命周期与状态

新增以下拟议交互命令：

- `org-wiki-qmd-setup`：检查程序和版本，创建专用缓存、索引及 collection。
- `org-wiki-qmd-sync`：同步已保存节点，增量生成缓存并运行文档索引更新。
- `org-wiki-qmd-embed`：使用显式配置的本地模型执行向量维护；模型须预先下载，查询和维护均不隐式下载模型。
- `org-wiki-qmd-status`：展示节点数、同步时间、就绪模式和最近失败原因。

同步使用独立的发现结果，包含文件列表、发现范围、各来源是否成功及失败原因。默认 `root-and-roam` 要求根目录枚举和 org-roam 查询均成功；成功查询得到零行与数据库缺失、不可用或查询异常必须区分。`root-only` 仅检查根目录，但必须由用户显式配置。目录不存在、无法读取候选文件或解析失败均视为发现不完整；单个节点缺少或重复 ID 则按第 3 节排除并诊断，不等同于来源故障。

发现不完整时中止本次同步，不更新缓存和 manifest，不删除旧缓存，也不发布新代次；状态报告具体来源错误。若上次提交仍完整，可按原有命中校验规则继续查询该代次。只有所配置范围完整扫描成功，才能根据与已提交 manifest 的差异判定删除、移出 wiki 或 ID 变化。显式缩小发现范围也须完成新范围的完整扫描，才能清理被排除的缓存。

同步提交协议如下，单个文件的原子替换只用于防止半写，不能替代整次同步的提交标记：

1. 取得维护锁，完成发现、节点验证和待发布内容准备；发现失败或有未保存的候选 buffer 时在修改已发布数据前退出。
2. 分配新的同步代次，在派生目录中持久化 `updating` 状态和目标代次，再修改缓存或启动 qmd 维护。状态文件原子替换；此后所有查询实例将 qmd 视为未就绪。
3. 增量替换缓存，生成该代次的待提交 manifest，移除确认失效且属于本集成的旧缓存。未改变的缓存不重写；删除路径必须受拥有关系和缓存目录边界约束。
4. 运行 qmd 文档更新，验证进程成功、索引存在以及来源内容未在准备后发生变化。若来源已变化、中断或更新失败，保留未完成状态，禁止发布就绪。
5. 原子替换已提交 manifest，最后原子发布包含同一代次和 manifest 摘要的 `ready` 状态，再释放维护锁。只有状态与 manifest 一致才可查询。文档同步发布关键词就绪；向量就绪绑定文档代次，内容变化后必须重新完成 embedding 才能发布相应模式就绪。

同一知识库的 setup、sync、embed 共用跨 Emacs 进程的文件系统维护锁；锁记录拥有者和任务信息，不能只用进程内变量或超时判断互斥。只有确认拥有者及其维护子进程已结束后才能接管遗留锁；无法确认时保留锁并给出诊断。知识库身份同时约束缓存、锁和专用 qmd 索引的归属，拒绝不同知识库误用同一索引。

查询在启动前和结果返回前检查持久化状态与代次；期间出现维护锁、状态不一致或代次变化时丢弃该次 qmd 结果并回退，避免已启动的查询跨越同步边界。重启时发现 `updating`、缺失状态或 manifest 摘要不匹配，都保持未就绪。下一次同步重新完整发现并核对缓存、重跑 qmd 更新，成功后才发布新代次；不能仅清除失败标记并沿用可能已部分更新的索引。恢复和重建只涉及派生数据。

首版采用手动同步，索引以已保存的文件为准。遇到未保存的候选 buffer 时提示并跳过此次发布，避免悄悄索引旧磁盘内容。已知有修改后，状态标记为待同步；返回命中前发现原节点失效或内容过期时丢弃命中。外部新增内容在下次同步前可能无法被 qmd 召回，这一最终一致性限制需要写进 README。

后续可增加可选的保存后空闲同步；保存钩子只标记和调度，不直接启动耗时 embedding。状态检测基于自有 manifest、进程结果及官方公开命令，不读取 qmd 私有 SQLite 表。

## 7. 实施顺序与交付物

按依赖关系拆成以下阶段，每阶段可独立评审：

| 阶段 | 工作与文件 | 完成条件 |
| --- | --- | --- |
| P0：验证 CLI 契约 | 在临时语料上验证版本、JSON、URI、参数解析、取消及 collection 更新范围；保存最小输出 fixture | 固定一个实测 qmd 版本，记录真实输出；不依赖猜测的字段或选项 |
| P1：生成节点缓存 | `org-wiki-qmd.el` 与测试：完整性发现、受控转换、manifest、增量同步、基础进程管理、跨进程维护锁、持久化代次及恢复；`org-wiki.el` 与测试：层级感知摘要；提供最小 setup、sync、status | 混合文件、嵌套节点、双 ID、根目录外节点和删除场景映射正确；发现失败不清理，发布中断可恢复；原始文件无变化 |
| P2：接通关键词搜索 | `org-wiki.el`：路由；qmd 模块：搜索进程封装、JSON、去重、校验、ID 位置登记、代次检查、回退 | `search` 模式经三个入口均能返回 canonical ID；空或过期位置表下仍能完成搜索、读取和跳转；未完成代次不被查询 |
| P3：增加语义检索 | `vsearch`、`query` 模式、显式 embedding、模式就绪检测 | 近义改写问题能够召回预期节点；模型缺失或超时能回退 |
| P4：完善维护体验 | 完善已有 setup、sync、embed、status 的进度展示、诊断和恢复提示 | 用户能区分未配置、来源发现不完整、未同步、待 embedding 和后端故障，并完成恢复 |
| P5：完成打包和文档 | README、Makefile、Eask、flake.nix、覆盖率与独立集成检查 | 新文件进入发布与检查清单；安装、首次索引、搜索和回退说明可复现 |

P1、P2 可先提供显式 `qmd` 模式；最小维护命令、互斥、代次检查和恢复必须随这两个阶段交付，不能推迟到 P4。待状态检查及恢复测试通过后再启用 `auto` 对 qmd 的自动选择。普通安装无需 qmd；真实 qmd 与模型只在专门的集成环境中准备。

## 8. 验证与验收

单元与适配测试使用临时 Org fixture 和可控的假 CLI，覆盖以下行为：

- 节点身份：普通节点被排除、子标题命中归属正确、双 ID 返回标题 ID、同文件多个 wiki 节点互不混淆。
- 摘要归属：一级、二级及更深 wiki 节点的直属 Summary 均可提取；无直属 Summary、多个 Summary、Summary 自身为 wiki 节点及 Summary 内嵌 wiki 子树时遵循第 3 节规则，父子缓存和摘要不串用。
- 语料范围：根目录外节点、符号链接、中文标题、空格路径及不同知识库缓存隔离。
- 发现完整性：org-roam 数据库缺失、查询抛错、根目录或候选文件读取失败时保留旧缓存和 manifest；成功返回空集才允许相应清理；显式 `root-only` 与默认范围分别验证。
- 生命周期：新增、修改、移动、删除、取消 wiki 标记、重复 ID、未保存 buffer，以及同步中断后的恢复。
- 提交恢复：在写入 `updating` 后、部分缓存替换后、qmd 更新中、qmd 成功但 manifest 未提交、manifest 已提交但 `ready` 未发布等位置注入中断；使用新的 Emacs 进程验证均不读取未完成代次，重新同步后恢复。另测双进程维护互斥、遗留锁接管和查询跨代次时回退。
- ID 闭环：根目录外节点在空位置表、旧路径位置表和重启后的搜索均可登记正确位置，随后读取、生成引用并通过交互访问函数定位同一标题；有效重复 ID 不被覆盖。
- 搜索契约：排名、去重、`k`、空查询、空结果，以及失效命中过滤后的回退。
- 可选开关：默认关闭；已安装程序且已有就绪索引时，关闭开关后 Emacs、MCP、gptel 搜索均不启动 qmd；显式 `qmd` 后端也不能绕过关闭状态。覆盖运行中切换后下一次查询的路由、重新开启时的就绪检查，以及 setup 不隐式开启搜索。
- 进程边界：程序缺失、非零退出、超时、`C-g`、损坏 JSON、stderr 输出、特殊字符与选项形态的查询。
- 接口兼容：MCP 和 gptel 的原工具参数、JSON 结构保持兼容；Emacs 前缀搜索绕过所有外部后端。

真实 qmd 集成测试分两层：关键词测试不下载模型；语义测试使用预先准备并固定的模型。普通 `make check` 保持离线、确定性，不因可选 qmd 未安装而失败。新增模块与测试需加入 Makefile、Eask、Nix 的显式文件列表，并纳入覆盖率配置；既有 fuzz 和基准测试显式绑定原后端，避免本机配置引入外部进程。

搜索效果用一份人工标注的中文与英文查询集评估，分别覆盖精确词、近义改写和多节点主题；记录各模式的 Recall@10、排序质量、冷启动/热查询耗时、首次索引耗时和磁盘占用。先取得基线，再决定是否把 `query` 设为默认模式。

最终验收必须满足：

1. 同一批查询能从 Emacs、MCP、gptel 获得一致的节点结果，搜索所得 ID 可以读取、生成原有 `id:` 引用并跳转到同一标题；根目录外节点和空或过期 ID 位置表同样通过。
2. 关键词模式完成精确查询闭环；语义模式在预先标注的改写样例中召回预期节点。
3. qmd 未安装、索引缺失、模型不可用和超时均按路由规则降级，主动取消能及时结束。
4. 同步后新增节点可搜、删除节点消失；查询结果不暴露缓存路径，操作不改写 Org 正文。
5. 通过项目既有 `make check`、Nix 构建及新增的真实 qmd 集成检查。
6. 发现失败不触发缓存清理；同步中断、重启和多个 Emacs 实例不会暴露未完成代次，重新同步可以恢复。
7. 任意支持层级的 wiki 节点均能取得自己的直属 Summary，父节点的缓存和摘要不混入嵌套 wiki 内容。
8. 默认安装和使用无需 qmd；搜索开关关闭时三个入口均不调用 qmd，默认 `auto` 保持原有搜索行为；开关切换不删除索引或触发维护。

## 9. CLI 契约和后续评估

P0 契约已针对 qmd 2.8.3 固定并保存在仓库中，覆盖以下事项；更换支持版本时必须重新验证：

- 精确支持版本、各模式 JSON 的字段和 URI 形式、查询字符串的参数边界。
- 命名索引在所选版本中的配置和数据库隔离行为，以及固定工作目录的配置优先级。
- 本地模型与文档代次的就绪检查，避免缺少 embedding 或模型时在查询中尝试自动准备。
- 基于 Org AST 的受控转换，不调用导出器，保留链接说明、代码文本和嵌套节点边界。

官方 `main` 是可变参考；实现和集成检查固定到 qmd 2.8.3。关键词与语义真实集成检查独立于离线门禁。完整的中英文查询集、Recall@10 和资源占用评估不由小语料集成检查替代，完成评估前保持 `search` 为默认模式。
